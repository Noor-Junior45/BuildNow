## 2025-03-05 - [Critical] Unauthenticated IDOR in API Order Deletion
**Vulnerability:** The API endpoints `DELETE /api/orders/:id`, `DELETE /api/orders`, and `POST /api/orders/clear` in `server.ts` were publicly accessible and bypassed Row Level Security (RLS) entirely by using the `SUPABASE_SERVICE_ROLE_KEY` to delete records. Anyone could delete any order by knowing its ID, or clear all orders for a given email or userId without authentication.
**Learning:** Using a service role key bypasses database-level access controls. When exposing database operations via backend endpoints instead of direct client queries, the backend MUST implement its own authorization matching the business rules.
**Prevention:** Implement a custom middleware (like `requireUserAuth`) that verifies the user's Supabase JWT from the `Authorization: Bearer <token>` header, injects the user context, and ensures that delete/modify operations explicitly enforce ownership bounds (e.g., `user.id === order.user_id`) before applying administrative service role privileges to the database action.
