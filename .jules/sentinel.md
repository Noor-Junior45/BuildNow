## $(date +%Y-%m-%d) - [CRITICAL] Replaced Admin API Key Middleware with User JWT Auth on Client-Facing Endpoint
**Vulnerability:** The `/api/notify-order` endpoint was protected by `requireApiSecret`, an admin middleware expecting a static `API_SECRET_KEY`. This endpoint is designed to be called by the frontend client, which fundamentally cannot securely store a static admin API key. As a result, the endpoint was uncallable or vulnerable to exposure if the secret key was leaked to clients. Furthermore, there were no IDOR checks preventing an authenticated user from triggering notifications for orders belonging to others.
**Learning:** Client-facing API endpoints must use dynamic user-level authentication (e.g., JWT) rather than static, globally shared admin API keys. When utilizing admin/service-role database clients (`getServerSupabase()`), rigorous ownership checks must be implemented in the application layer to enforce authorization and prevent IDOR.
**Prevention:** Always use `requireUserAuth` (verifying Supabase session tokens) for endpoints interacting with the frontend. Implement strict data ownership validations (matching `user.id`, `phone`, or `email`) before executing actions on sensitive resources when bypassing database-level RLS. Ensure robust edge-case handling (e.g., preventing empty string matches) when comparing identifiers.
